## 🏗️ System Architecture

본 프로젝트는 싱글톤 패턴 기반의 매니저 구조와 정적 헬퍼 클래스를 활용하여 객체의 책임과 역할을 명확히 분리하고, 안정적인 라이프사이클을 유지하도록 설계되었습니다.

### 1. 매니저 클래스 (Managers)
전역적인 상태를 제어하며, 프로그램 실행 동안 유일한 인스턴스로 유지됩니다.
*   **InventoryManager**: 플레이어의 아이템 재고(`PotionInventory`) 및 전체 리스트를 관리합니다. 아이템 추가 시 자동 정렬 및 중복 체크 로직을 수행합니다.
*   **ItemManager**: 게임 내 모든 아이템의 원형(Prototype) 데이터를 보관하고 관리하여 데이터의 일관성을 유지합니다.
*   **PlayerManager**: 플레이어의 HP, MP 등 주요 능력치와 상태 변화를 제어합니다.

### 2. 정적 및 유틸리티 클래스 (Static / Helpers)
특정 인스턴스에 종속되지 않고 공통 기능을 제공하는 보조 클래스입니다.
*   **InputHelper**: 콘솔 입력의 유효성 검사(범위 및 타입 체크)를 담당하는 정적 클래스입니다.
*   **BattleInventory (UI)**: 전투 중 인벤토리 루프를 관리합니다. `std::unordered_map` 데이터를 출력용 `std::vector`로 가공하여 사용자에게 유동적인 리스트를 제공합니다.

### 3. 프로그램 라이프사이클 (Life Cycle)

프로그램은 **초기화 -> 루프 -> 종료**의 엄격한 순서를 따르며, 특히 다형성을 활용한 안정적인 메모리 해제에 집중했습니다.

#### **Step 1: Initialize (초기화)**
*   싱글톤 매니저 인스턴스 할당 및 초기화.
*   아이템 데이터베이스 빌드 및 플레이어 초기 정보 로드.

#### **Step 2: Execution (실행 및 상태 전환)**
*   **Main Loop**: 유저 입력을 처리하고 각 매니저를 통해 게임 로직을 수행합니다.
*   **Sub Loop (Context Switch)**: 전투나 인벤토리 진입 시 별도의 루프(`Enter()`)로 전환되며, `bIsEnter` 플래그를 통해 흐름을 제어합니다.
*   **Data Processing**: 인터페이스 다중 상속을 통해 `IHitable`, `ISavable` 등의 기능을 객체에 유연하게 부여합니다.

#### **Step 3: Terminate (종료)**
*   **Safe Destruction**: 최상위 인터페이스 및 베이스 클래스에 선언된 **가상 소멸자(Virtual Destructor)**를 통해, 상속 관계에 있는 모든 객체를 메모리 누수 없이 역순으로 안전하게 해제합니다.

### 4. 데이터 모델링 및 객체화 구조 (Data Modeling)

단순한 기능 구현을 넘어, 데이터와 로직을 분리하고 상속을 통한 확장성을 고려하여 객체화하였습니다.

#### **A. Item & Data Class (Flyweight Pattern Concept)**
*   **ItemData (Base)**: 모든 아이템의 공통 속성(ID, 이름, 설명, 가격 등)을 정의하는 데이터 클래스입니다.
*   **PotionData (Derived)**: `ItemData`를 상속받으며, 포션 고유의 속성(회복량, 효과 타입)을 추가로 가집니다.
*   **구현 특징**: 인벤토리는 실제 객체 전체를 들고 있는 대신, `ItemData*` 포인터를 참조하여 메모리 효율을 높였습니다.

#### **B. Entity Inheritance (Monster & Player)**
모든 생동하는 객체는 최상위 인터페이스로부터 기능을 부여받고, 베이스 클래스를 통해 공통 로직을 상속받습니다.



*   **Interfaces (`IBattleObject`)**: '타격 가능함', '피격 가능함' 등의 추상적인 행위를 정의합니다.
*   **CreatureBase (Abstract Class)**: 이름, HP, MP, 공격력 등 모든 생명체의 공통 스탯과 `TakeDamage()` 같은 핵심 로직을 포함합니다.
*   **Player & Monster (Concrete Class)**:
    *   **Player**: 레벨업 시스템, 경험치 관리, 인벤토리 상호작용 로직이 추가됩니다.
    *   **Monster**: 종족별 고유 AI 패턴, 드랍 아이템 테이블 로직을 개별적으로 구현합니다.

#### **C. 객체 생성 및 관리 (Factory Concept)**
*   몬스터나 아이템 객체 생성 시 직접적인 `new` 호출을 최소화하고, `ItemManager`나 전용 생성 로직을 통해 규격화된 데이터를 주입받아 객체화합니다. 
*   이를 통해 데이터의 오염을 방지하고, 새로운 몬스터나 아이템 추가 시 기존 코드를 크게 수정하지 않아도 되는 확장성을 확보했습니다.
